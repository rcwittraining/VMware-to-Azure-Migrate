Student and instructor guide for the interactive simulator. The lab mirrors Microsoft’s agentless VMware path: project → appliance OVA → Configuration Manager registration → discovery → assessment → replication → test migration → planned cutover.

Duration 90–120 min Level Intermediate Maps to AZ-104 / AZ-305 / AZ-801

1. Scenario

Contoso Ltd. is leaving its Chennai colocation facility. Wave 1 is four VMware VMs on vcenter.contoso.local. Leadership wants a repeatable Azure Migrate factory. Your job is to stand up the project and appliance, then migrate the customer-facing web server WEB-01 with a planned cutover.

2. Architecture (agentless)

  1. Azure Migrate project holds metadata and orchestrates tools.
  2. The appliance VM (OVA) runs Discovery, Assessment, DRA, and Gateway services.
  3. Appliance talks to vCenter :443 for inventory and snapshot orchestration.
  4. For replication, appliance + VDDK reads disks from ESXi :902/443 using CBT snapshots. No Mobility agent in the guest.
  5. Replicated data is uploaded to Azure over TCP 443.
  6. Test migration boots a copy in an isolated VNet. Planned migration shuts down the source, applies the last delta, and creates the production Azure VM.

3. Lab modules (do in order)

Module 0 — Sign in

  1. Start the lab and sign in to the simulated portal as admin@contoso.com.

Module 1 — Create the Azure Migrate project

  1. Search for Azure Migrate (do not jump via a random tile only — practice portal search).
  2. Create project: RG rg-migrate-prod, name contoso-vmware-migrate, geography Asia.
  3. Wait for Microsoft.Migrate and the Discovery/Migration tools to attach.
Geography is where metadata lives. You can still migrate WEB-01 to East US.

Module 2 — Generate the project key and download the OVA

  1. In Discovery and assessment, select Discover.
  2. Machines virtualized? Yes, with VMware vSphere. Method: appliance.
  3. Appliance name contosoappl01 → Generate key. Do not close the blade while resources are created (Key Vault, storage, app registration).
  4. Copy the project key. Download the VMware OVA.

Module 3 — Deploy the appliance on vCenter

  1. Open the vSphere Client and sign in as migrate-svc@vsphere.local.
  2. Deploy OVF Template: source OVA → name AzureMigrateAppl → folder Migrate → compute Prod-Cluster → vsanDatastore → Thick Lazy Zeroed → network VM-Network (not Isolated-Lab).
  3. Power on. Confirm DHCP address 10.10.1.50.

Module 4 — Configure and register the appliance

  1. Open https://10.10.1.50:44368.
  2. Run connectivity, time-sync, and URL checks.
  3. Paste the project key → verify → wait for auto-update of Discovery, Assessment, DRA, Gateway.
  4. Login with the device code as admin@contoso.com. Confirm registration against the project.
  5. Install VDDK 8.0 (required for agentless disk reads).

Module 5 — Start continuous discovery

  1. Add credentials: friendly name vcenter-prod, user migrate-svc@vsphere.local.
  2. Add discovery source vcenter.contoso.local port 443.
  3. Enable software inventory + agentless dependency analysis. Start discovery.
Minimum for discovery: vCenter Read-only at datacenter with propagate. Add Guest Operations for software inventory. Replication later needs snapshot, datastore, and VM config privileges.

Module 6 — Review inventory

In the portal, wait until four servers appear. Open WEB-01 and confirm VMware Tools, 80 GB OS disk, and IP 10.10.20.11.

Module 7 — Assessment

  1. Create assessment Assess-Contoso-Wave1, type Azure VM.
  2. New group Wave1-VMware including WEB-01 (include all four in the lab).
  3. Target East US, sizing Performance-based, pay-as-you-go.
  4. Review readiness: SQL-01 is Ready with conditions because of data-disk IOPS.

Module 8 — Replicate WEB-01

  1. Migration and modernization → Replicate → VMware → appliance contosoappl01 → Agentless.
  2. Select WEB-01. Target RG rg-migrate-prod, East US, vnet-landing-eus / snet-web, size Standard_D4s_v5. Enable Hybrid Benefit.
  3. Wait until status is Protected (100%). Initial replication uses a snapshot; CBT then ships deltas.

Module 9 — Test migration

  1. Test migrate WEB-01 into vnet-test-eus (never the production VNet).
  2. Confirm the test VM reaches Running. The source VM stays up; replication continues.
  3. Clean up the test migration (deletes the test Azure VM and NICs).

Module 10 — Planned cutover

  1. Migrate → Yes, shut down for a planned migration with no data loss.
  2. Appliance powers off WEB-01 via vCenter, sends the last delta, creates the Azure VM (10.20.1.11).
  3. Verify the VM is Running. Stop replication. Plan DNS cutover and source retirement on the next CAB window.

Module 11 — Knowledge check

Pass with 70% or higher. Topics: project geography, appliance name rules, ports, VDDK, agentless vs agent-based, assessment types, test vs planned migration, appliance scale (10,000 VMs), vCenter roles.

5. Instructor notes

  • Expected key prefix: CONTOSOAPPL01@MIGRATE@… (generated in-sim).
  • Wrong appliance network (Isolated-Lab) is a deliberate fail path.
  • Unplanned migrate (no shutdown) is rejected so students practice the no-data-loss option.
  • Production would wait ≥24 hours of performance history before a sizing assessment; the simulator compresses that.
  • Official docs: Create a project, Set up the VMware appliance, Discover VMware, Agentless vs agent-based.

6. Success criteria

  • Project and RG named to standard; appliance registered; VDDK installed.
  • Four VMs discovered; Wave1 assessment exists; WEB-01 Protected then Migrated.
  • Test migration used vnet-test-eus and was cleaned up.
  • Knowledge check ≥ 70%.
